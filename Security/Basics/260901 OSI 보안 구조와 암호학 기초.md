# OSI 보안 구조와 암호학 기초

## 1. OSI 보안 구조

OSI 보안 구조는 크게 다음 세 가지로 나눠서 이해한다.

1. 보안 공격(Security Attack)
2. 보안 서비스(Security Service)
3. 보안 메커니즘(Security Mechanism)

쉽게 말하면 다음 흐름이다.

`공격이 들어옴 → 어떤 보안 속성을 지켜야 하는가 → 어떤 기술로 보호할 것인가`

예를 들어 스누핑 공격이 발생하면 기밀성이 위협받고, 이를 보호하기 위해 암호화를 사용할 수 있다.

---

## 2. 보안 공격

### 2.1 기밀성을 위협하는 공격

#### Snooping

비인가 사용자가 데이터를 몰래 보거나 탈취하는 공격이다.

예를 들어 네트워크에서 전송 중인 파일이나 메시지를 가로채 내용을 읽는 경우다.

대표 대응은 암호화다. 데이터를 가로채더라도 내용을 이해하지 못하게 만든다.

#### Traffic Analysis

데이터 내용이 암호화되어 있어도 통신 패턴을 관찰해 정보를 추측하는 공격이다.

예를 들면 다음과 같은 정보를 볼 수 있다.

- 누가 누구와 통신하는지
- 언제 통신하는지
- 얼마나 자주 통신하는지
- 전송 데이터의 크기가 어느 정도인지

내용을 직접 보지 않아도 조직의 행동이나 통신 패턴을 추측할 수 있다.

### 2.2 무결성을 위협하는 공격

#### Modification

정상 메시지의 내용을 수정하거나 전송을 지연시키거나 순서를 바꾸는 공격이다.

#### Masquerading

공격자가 다른 사용자나 시스템인 것처럼 위장하는 공격이다.

#### Replaying

정상 데이터를 획득해 저장한 뒤 나중에 다시 전송하는 공격이다.

#### Repudiation

송신자나 수신자가 나중에 메시지를 보냈거나 받았다는 사실을 부인하는 것이다.

이를 막는 개념이 Non-repudiation(부인방지)이다.

### 2.3 가용성을 위협하는 공격

#### Denial of Service (DoS)

시스템의 자원을 소진시키거나 서비스를 느리게 만들어 정상 사용자가 서비스를 이용하지 못하게 하는 공격이다.

보안이 잘 되어 있어도 DDoS를 100% 막는다고 보기보다는 탐지, 차단, 분산, 복구 등을 통해 영향을 줄이고 버티는 것이 중요하다.

---

## 3. 수동 공격과 능동 공격

### Passive Attack

공격자가 정보를 얻기만 하고 데이터나 시스템 자체를 변경하지 않는 공격이다.

대표 공격:

- Snooping
- Traffic Analysis

특징:

- 기밀성을 위협한다.
- 공격자가 조용히 관찰하기 때문에 탐지가 어렵다.
- 따라서 탐지보다 예방이 중요하다.

한 줄 정리:

`수동 공격 = 시스템은 멀쩡하지만 비밀이 새는 공격`

### Active Attack

공격자가 데이터를 변경하거나 시스템 동작에 영향을 주는 공격이다.

대표 공격:

- Modification
- Masquerading
- Replaying
- Repudiation
- DoS

특징:

- 무결성과 가용성을 위협한다.
- 시스템에 변화가 발생하므로 수동 공격보다 상대적으로 탐지가 쉽다.
- 실제 능동 공격 전에 수동 공격으로 정보를 수집하는 경우도 많다.

한 줄 정리:

`Passive = 훔쳐본다`

`Active = 건드린다`

## 4. 보안 서비스

### 4.1 Authentication

주장한 신원이 진짜인지 확인하는 것이다.

- 식별: "나는 또또다"
- 인증: "진짜 또또가 맞는지 증명해봐"

Masquerading과 같은 신분 위장 공격을 막는 데 중요하다.

### 4.2 Access Control

인증된 사용자가 허용된 자원과 기능만 사용하도록 제한하는 것이다.

흐름:

`식별 → 인증 → 접근통제`

예를 들어 로그인에 성공했더라도 일반 사용자는 조회만 가능하고 관리자는 수정과 삭제까지 가능하게 권한을 나눌 수 있다.

### 4.3 Confidentiality

허가받지 않은 사용자가 정보를 보지 못하도록 보호하는 것이다.

대표적인 보호 방법은 암호화다.

- Snooping은 데이터 내용을 노린다.
- Traffic Analysis는 통신 패턴을 노린다.

### 4.4 Integrity

데이터가 인가되지 않은 방식으로 변경되지 않았음을 보장하는 것이다.

예를 들어 `10만원 송금`이라는 메시지가 중간에서 `1000만원 송금`으로 바뀌면 무결성이 깨진 것이다.

해시, MAC/HMAC, 전자서명 등이 무결성 검증에 사용될 수 있다.

### 4.5 Non-repudiation

송신자나 수신자가 나중에 자신의 행위를 부인하지 못하도록 하는 것이다.

- 송신 부인방지: "나는 보내지 않았다"고 부인하지 못하게 함
- 수신 부인방지: "나는 받지 않았다"고 부인하지 못하게 함

전자서명과 밀접한 관련이 있다.

인증과의 차이:

- 인증: 지금 너 맞아?
- 부인방지: 나중에 너 아니라고 못 해.

### 4.6 Availability

인가된 사용자가 필요할 때 시스템이나 서비스를 정상적으로 사용할 수 있도록 보장하는 것이다.

가용성 확보와 관련된 방법:

- 이중화
- Failover
- 백업
- Load Balancing
- 자원 모니터링
- DDoS 방어
- 재해복구

CIA를 짧게 외우면 다음과 같다.

- C: 못 보게
- I: 못 바꾸게
- A: 못 쓰게 되지 않게

---

## 5. 보안 메커니즘

보안 서비스가 "무엇을 보호할 것인가"라면 보안 메커니즘은 "실제로 어떻게 보호할 것인가"다.

대표적인 메커니즘:

- 암호화(Encipherment)
- 전자서명(Digital Signature)
- 접근통제(Access Control)
- 데이터 무결성 메커니즘
- 인증 교환(Authentication Exchange)
- 트래픽 패딩(Traffic Padding)
- 라우팅 제어(Routing Control)
- 공증(Notarization)

관계를 예로 들면 다음과 같다.

`Snooping → 기밀성 필요 → 암호화 사용`

# 암호학 기초

## 6. 암호화 기본 개념

암호학은 단순히 비밀을 숨기는 기술만이 아니라 데이터를 믿을 수 있게 만드는 기술 전체를 다룬다.

주요 목적:

- 기밀성
- 무결성
- 인증
- 부인방지

기본 용어:

- Plaintext(P): 평문
- Ciphertext(C): 암호문
- Encryption(E): 암호화
- Decryption(D): 복호화
- Key(K): 키

기호로 표현하면 다음과 같다.

`C = E_K(P)`

평문 P를 키 K로 암호화하면 암호문 C가 나온다는 뜻이다.

`P = D_K(C)`

암호문 C를 키 K로 복호화하면 다시 평문 P가 나온다는 뜻이다.

전체 흐름:

`P → E_K → C → D_K → P`

---

## 7. 암호화와 해시의 차이

암호화는 원래 데이터로 되돌리는 복호화 과정이 존재한다.

`평문 → 암호문 → 평문`

반면 해시는 원래 값으로 되돌리는 복호화 과정이 없다.

`평문 → 해시값`

비밀번호는 서버가 원래 비밀번호를 다시 읽을 필요가 없고 입력한 값이 기존 값과 같은지만 확인하면 되므로 해시 방식으로 저장하는 것이 적합하다.

해시된 비밀번호 DB가 탈취되어도 공격자가 원문 비밀번호를 바로 얻는 것은 아니다. 비밀번호 후보를 반복해서 계산하며 해시값과 비교하는 오프라인 크래킹을 해야 한다.

유출된 해시가 아직 깨지기 전에 비밀번호를 변경하면 기존 해시는 해당 서비스 로그인에 더 이상 직접 사용할 수 없다. 단, 같은 비밀번호를 다른 서비스에서도 사용했다면 그 서비스들도 함께 변경해야 한다.

---

## 8. Salt

Salt는 비밀번호에 랜덤값을 추가한 뒤 해시하는 방식이다.

예를 들어 사용자 세 명이 모두 비밀번호 `1234`를 사용한다고 가정한다.

Salt가 없다면:

```text
A: 1234 → AAA111
B: 1234 → AAA111
C: 1234 → AAA111
```

같은 비밀번호는 같은 해시값이 나온다.

Salt를 사용하면:

```text
A: 1234 + X7 → QWE999
B: 1234 + B2 → ZXC555
C: 1234 + K9 → ASD777
```

같은 비밀번호를 사용하더라도 서로 다른 해시값이 만들어진다.

Salt 자체는 비밀일 필요가 없으며 일반적으로 해시값과 함께 저장할 수 있다.

Salt의 목적은 같은 비밀번호의 해시값이 같아지는 것을 막고 미리 계산된 Rainbow Table의 효율을 떨어뜨리는 것이다.

## 9. 암호에서 사용하는 이름

암호학 설명에서는 다음과 같은 이름을 관례적으로 사용한다.

- Alice: 보통 메시지를 보내는 사람
- Bob: 보통 메시지를 받는 사람
- Eve: 수동적 공격자, 도청자
- Mallory: 능동적 공격자, 메시지 변조/위조/재전송 가능
- Trent: 신뢰할 수 있는 제3자
- Victor: 검증자

특히 다음 연결을 기억하면 된다.

`Eve = Eavesdropper = Passive Attack`

`Mallory = Malicious = Active Attack`

## 10. 치환 암호와 전치 암호

### 치환(Substitution)

문자나 기호 자체를 다른 값으로 바꾸는 방식이다.

예:

`HELLO → KHOOR`

대표적인 예로 Caesar Cipher가 있다.

### 전치(Transposition)

문자 자체는 그대로 두고 위치나 순서만 바꾸는 방식이다.

예:

`HELLO → HLOEL`

짧게 외우면:

- 치환 = 사람을 바꿈
- 전치 = 자리만 바꿈

현대 암호에서도 값을 바꾸고 위치를 섞는 아이디어가 발전된 형태로 사용되기 때문에 기초 개념으로 알아둔다.

---

## 11. 대칭키 암호

암호화와 복호화에 같은 비밀키를 사용하는 방식이다.

```text
평문 + 비밀키 K → 암호문
암호문 + 같은 비밀키 K → 평문
```

장점:

- 빠르다.
- 대량 데이터 암호화에 적합하다.

단점:

- 상대방과 같은 비밀키를 미리 공유해야 한다.
- 이 비밀키를 안전하게 전달하는 것이 문제다.

---

## 12. 비대칭키 암호

공개키와 개인키라는 서로 다른 두 개의 키를 사용하는 방식이다.

가장 쉬운 비유:

- 공개키 = 누구나 사용할 수 있는 공용 자물쇠
- 개인키 = 그 자물쇠를 여는 나만 가진 열쇠

상대방이 나에게 비밀 메시지를 보내고 싶다면 내 공개키로 암호화해 보낸다. 이 암호문은 내 개인키로만 복호화할 수 있다.

즉:

`내 공개키로 잠금 → 내 개인키로 열기`

공개키는 다른 사람에게 공개해도 되지만 개인키는 나만 가지고 있어야 한다.

비대칭키가 필요한 핵심 이유는 처음 만난 상대와 비밀키를 안전하게 공유하기 어렵다는 대칭키의 문제를 해결하기 위해서다.

---

## 13. HTTPS와 대칭키/비대칭키

HTTPS에서는 대칭키와 비대칭키를 함께 사용한다.

브라우저와 서버가 처음 만났을 때는 아직 둘이 공유하는 비밀키가 없다.

그런데 그 비밀키를 인터넷으로 평문 전송하면 중간에서 누군가 훔쳐볼 수 있다.

그래서 처음 연결을 안전하게 만들 때 비대칭키 기반 기술을 사용한다.

이해를 위한 단순화된 흐름:

1. 서버가 공개키가 포함된 인증서를 브라우저에 제공한다.
2. 브라우저는 서버의 신원을 확인한다.
3. 비대칭키 기반 기술을 이용해 둘만 사용할 세션키를 안전하게 정한다.
4. 이후 실제 웹 통신은 빠른 대칭키로 암호화한다.

즉:

`비대칭키 = 처음 안전하게 만나기`

`대칭키 = 이후 실제 데이터를 빠르게 암호화하기`

현대 TLS에서는 ECDHE 등을 이용해 양쪽이 세션키를 함께 만들어내는 방식이 일반적이지만, 핵심 개념은 "안전한 초기 연결에는 비대칭키 기술, 실제 데이터 통신에는 대칭키"라고 이해하면 된다.

---

## 오늘의 핵심 요약

- Passive Attack은 정보를 훔쳐보기만 하며 기밀성을 위협한다.
- Active Attack은 데이터를 변경하거나 시스템에 영향을 준다.
- 보안 서비스는 인증, 접근통제, 기밀성, 무결성, 부인방지, 가용성으로 이해한다.
- 암호화는 평문을 암호문으로 바꾸고 복호화할 수 있다.
- 해시는 복호화하지 않고 같은 값인지 확인하는 데 활용한다.
- Salt는 같은 비밀번호도 서로 다른 해시값이 나오게 만든다.
- 치환은 값을 바꾸고 전치는 순서를 바꾼다.
- 대칭키는 빠르지만 키 공유가 어렵다.
- 비대칭키는 공개키(자물쇠)와 개인키(열쇠)를 사용한다.
- HTTPS는 초기 연결에 비대칭키 기반 기술을 활용하고 이후 실제 통신에는 대칭키를 사용한다.
