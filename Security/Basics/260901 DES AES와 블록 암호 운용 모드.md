# DES, AES와 블록 암호 운용 모드

## 오늘 학습 범위

오늘은 대칭키 암호 중 DES와 AES를 다시 복습하고, AES를 여러 블록에 적용할 때 사용하는 블록 암호 운용 모드까지 살펴봤다.

학습한 범위:

- DES와 AES의 차이
- DES 56비트 키와 AES-128의 키 공간 차이
- AES가 빠른 이유
- 3DES가 느린 이유 복습
- 블록 암호 운용 모드 개념
- ECB
- CBC
- IV
- CTR
- CFB
- OFB

---

## 1. DES와 AES

둘 다 대칭키 암호다.

즉 암호화와 복호화에 같은 비밀키를 사용한다.

### DES

DES(Data Encryption Standard)는 오래된 대칭키 블록 암호다.

주요 특징:

- 블록 크기: 64비트
- 실제 키 길이: 56비트
- 현재 기준으로는 키 공간이 너무 작아서 안전하지 않다.

DES의 가능한 키 개수는 다음과 같다.

`2^56 ≈ 7.2 × 10^16`

### AES

AES(Advanced Encryption Standard)는 DES를 대체한 현대적인 대칭키 블록 암호다.

주요 특징:

- 블록 크기: 128비트
- 키 길이: 128 / 192 / 256비트
- 현대 시스템에서 널리 사용된다.

AES-128의 가능한 키 개수는 다음과 같다.

`2^128 ≈ 3.4 × 10^38`

DES와 AES-128의 키 공간 차이는 다음과 같다.

`2^128 / 2^56 = 2^72`

즉 AES-128의 키 경우의 수가 DES보다 약 `4.7 × 10^21배` 많다.

핵심:

`DES = 56비트라 현재는 너무 약함`

`AES = 훨씬 큰 키 공간을 사용하며 현재 표준으로 널리 사용`

---

## 2. AES가 빠른 이유

키 길이가 길다고 반드시 느린 것은 아니다.

AES는 현대 컴퓨터가 효율적으로 처리할 수 있는 연산을 중심으로 설계되었다.

대표적으로 다음과 같은 연산을 반복한다.

- 바이트 치환
- 위치 섞기
- 값 섞기
- XOR

특히 XOR 같은 비트 연산은 CPU가 매우 빠르게 처리한다.

또 현대 CPU에는 AES 연산을 빠르게 처리하기 위한 전용 명령어(AES-NI 등)가 있는 경우가 많다.

따라서 AES는 강한 보안성을 가지면서도 실제 시스템에서 매우 빠르게 동작한다.

3DES는 기존 DES 연산을 여러 번 반복해서 보안성을 늘린 방식이라 연산량이 많고 느리다.

# 블록 암호 운용 모드

AES는 데이터를 128비트 블록 단위로 처리한다.

하지만 실제 파일이나 네트워크 데이터는 128비트보다 훨씬 크다.

따라서 데이터를 여러 블록으로 나눈 뒤, 그 블록들을 어떤 방식으로 암호화할지를 정해야 한다.

이 방식을 블록 암호 운용 모드(Block Cipher Mode)라고 한다.

중요:

`AES = 실제 암호화 알고리즘`

`ECB/CBC/CTR/CFB/OFB = AES 같은 블록 암호를 여러 블록에 어떻게 적용할지 정하는 방식`

---

## 3. ECB

ECB(Electronic Codebook)는 각 블록을 서로 독립적으로 암호화한다.

예:

```text
AAAA | BBBB | AAAA
```

각각 독립적으로 AES를 수행하면:

```text
AAAA → X
BBBB → Y
AAAA → X
```

결과:

```text
X | Y | X
```

같은 평문 블록은 같은 암호문 블록으로 나온다.

따라서 공격자가 실제 내용을 모르더라도 반복되는 패턴을 알 수 있다.

핵심:

`ECB = 각자 독립적으로 암호화 → 같은 평문은 같은 암호문 → 패턴 노출`

현재 일반적인 데이터 암호화 용도로는 거의 사용하지 않는다.

---

## 4. CBC

CBC(Cipher Block Chaining)는 블록을 체인처럼 연결한다.

이전 블록의 암호문을 다음 평문 블록에 섞은 뒤 암호화한다.

예:

```text
AAAA + IV → AES → X
BBBB + X  → AES → Y
AAAA + Y  → AES → Z
```

같은 AAAA가 다시 등장해도 앞에서 섞이는 값이 다르기 때문에 암호문 결과가 달라진다.

핵심:

`CBC = 이전 암호문을 다음 평문에 섞어서 암호화`

### IV

CBC의 첫 번째 블록은 앞에 암호문이 없기 때문에 처음에 임의의 값을 하나 사용한다.

이를 IV(Initialization Vector, 초기화 벡터)라고 한다.

IV를 다르게 사용하면 같은 평문과 같은 키를 사용하더라도 첫 블록의 암호문이 달라질 수 있다.

비밀키와 달리 IV 자체는 일반적으로 비밀일 필요는 없다.

---

## 5. CTR

CTR(Counter Mode)은 이전 블록의 암호문을 사용하지 않는다.

대신 카운터 값을 사용한다.

예를 들면 다음처럼 번호를 만든다.

```text
1
2
3
4
...
```

각 카운터를 AES로 암호화한다.

```text
1 → AES → A
2 → AES → B
3 → AES → C
```

그리고 이 값을 실제 평문과 XOR한다.

```text
평문1 XOR A → 암호문1
평문2 XOR B → 암호문2
평문3 XOR C → 암호문3
```

각 블록이 이전 블록 결과를 기다릴 필요가 없기 때문에 병렬 처리가 가능하다.

핵심:

`CTR = 카운터 값을 AES로 암호화한 뒤 평문과 XOR`

머릿속 이미지:

`ECB = 각자`

`CBC = 줄줄이 연결`

`CTR = 번호표`

---

## 6. CFB

CFB(Cipher Feedback)는 AES 같은 블록 암호를 스트림 암호처럼 사용할 수 있게 하는 방식이다.

이전 암호문을 다시 AES 입력으로 사용한다.

흐름:

```text
이전 암호문 → AES → 출력값 XOR 평문 → 새로운 암호문
```

첫 번째에는 이전 암호문이 없으므로 IV를 사용한다.

이름 그대로:

`Cipher Feedback = 암호문을 다시 피드백`

---

## 7. OFB

OFB(Output Feedback)는 CFB와 비슷하지만, 다음 단계에 암호문을 넣는 것이 아니라 AES의 출력값을 다시 넣는다.

흐름:

```text
IV → AES → 출력값 A
출력값 A → AES → 출력값 B
출력값 B → AES → 출력값 C
```

각 출력값을 평문과 XOR해서 암호문을 만든다.

이름 그대로:

`Output Feedback = AES 출력값을 다시 피드백`

---

## 8. 현재 이해 상태

ECB, CBC, CTR까지는 흐름을 어느 정도 이해했다.

특히 다음 정도는 기억하고 있다.

```text
ECB = 각 블록 독립
CBC = 앞 암호문을 다음 블록에 연결
CTR = 카운터 번호를 이용
```

하지만 CFB와 OFB까지 한꺼번에 보면서 운용 모드들이 서로 헷갈리기 시작했고, 앞에서 이해했던 ECB/CBC/CTR도 순간적으로 같이 헷갈렸다.

따라서 블록 암호 운용 모드는 오늘 완전히 끝낸 것으로 보지 않고 다음 학습 때 다시 복습하기로 했다.

다음에 다시 볼 때는 5개를 한꺼번에 외우기보다 다음 순서로 다시 확인한다.

```text
1. ECB
2. CBC + IV
3. CTR
4. 위 세 개 차이 복습
5. 그 다음 CFB / OFB
```

특히 각 방식의 구조를 외우는 것보다 먼저 다음 질문을 중심으로 다시 이해할 것.

- 왜 이 운용 모드가 필요한가?
- 이전 블록의 무엇을 다음 계산에 사용하는가?
- 실제로 어떤 상황에서 사용하는가?
- 같은 평문 블록이 반복되면 결과가 어떻게 되는가?
