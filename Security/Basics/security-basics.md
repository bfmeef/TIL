# 보안 기본 개념

## 한 줄 요약

정보보안은 허가된 사용자가 허가된 정보와 기능에 적절하게 접근할 수 있도록 보호하는 활동이다.

보안은 단순히 정보를 숨기는 것만 의미하지 않는다. 정보가 **함부로 노출되지 않고, 함부로 변경되지 않으며, 필요할 때 정상적으로 사용할 수 있는 상태**를 유지하는 것이 핵심이다.

---

## CIA 3요소

정보보안의 가장 기본적인 목표는 **기밀성(Confidentiality), 무결성(Integrity), 가용성(Availability)**이며, 이를 묶어 CIA Triad라고 한다.

### 기밀성 (Confidentiality)

허가되지 않은 사용자가 정보를 보지 못하도록 보호하는 성질이다.

쉽게 말하면 **"봐도 되는 사람만 보게 하는 것"**이다.

왜 중요한가?

정보는 단순한 데이터가 아니라 계정 권한, 개인정보, 돈, 회사 자산 등과 연결될 수 있다. 비밀번호가 노출되면 계정 탈취로 이어질 수 있고, 고객 정보가 유출되면 사칭이나 피싱 같은 2차 피해가 발생할 수 있다.

즉,

`기밀성 실패 → 정보 유출 → 유출된 정보를 이용한 2차 공격 → 실제 피해`

대표적인 보호 수단:
- 암호화
- 접근통제
- 인증
- 권한관리
- VPN

대표적인 침해 사례:
- 패킷을 몰래 가로채어 내용을 열람
- 고객 DB 유출
- 권한 없는 사용자의 내부 문서 열람

시험 포인트:

**비인가자가 정보를 열람하면 기밀성 침해**이다.

---

### 무결성 (Integrity)

정보가 허가 없이 변경되거나 훼손되지 않았음을 보장하는 성질이다.

쉽게 말하면 **"데이터를 함부로 건드리지 못하게 하고, 바뀌었다면 알아낼 수 있게 하는 것"**이다.

예를 들어 은행 DB의 잔액이 `100,000원`에서 `10,000,000원`으로 임의 변경되었다면 무결성이 침해된 것이다. 사용자 입장에서 이득처럼 보여도 시스템 관점에서는 장부 데이터의 신뢰성이 깨진 심각한 문제다.

대표적인 침해 사례:
- DB 값 임의 수정
- 파일 내용 변조
- 로그 삭제 또는 조작
- 송금 금액 변조
- 프로그램 코드 변경

대표적인 보호 수단:
- 해시
- MAC(Message Authentication Code)
- 전자서명
- 접근통제
- 변경 이력 관리

#### 해시와 무결성

파일의 해시값을 미리 저장해두고 나중에 다시 계산했을 때 값이 달라지면 내용이 변경되었다는 사실을 알 수 있다.

즉, 해시는 주로 **변조 여부를 탐지**하는 데 사용된다.

시험 포인트:

**비인가자가 데이터를 수정하거나 삭제하면 무결성 침해**이다.

---

### 가용성 (Availability)

필요한 사용자가 필요할 때 시스템이나 정보를 사용할 수 있도록 보장하는 성질이다.

쉽게 말하면 **"써야 할 때 서비스가 죽어 있지 않게 하는 것"**이다.

대표적인 침해 또는 원인:
- DoS / DDoS
- 서버 장애
- 네트워크 단절
- 디스크 장애
- 자원 고갈
- 랜섬웨어로 시스템 사용 불가

대표적인 보호 수단:
- 이중화
- 백업
- Failover
- 로드밸런싱
- DDoS 방어
- 모니터링

#### 일반 장애와 보안 사고의 차이

결과만 보면 둘 다 서비스가 중단될 수 있지만, 원인이 다르다.

- 서버 고장이나 설정 실수로 서비스 중단 → 일반 장애
- 공격자가 DDoS나 랜섬웨어 등으로 서비스를 중단 → 보안 사고

가용성이 보안 요소에 포함되는 이유는 공격자가 데이터를 훔치거나 변조하지 않더라도 **서비스 자체를 사용하지 못하게 만드는 것**을 공격 목표로 삼을 수 있기 때문이다.

시험 포인트:

**서비스를 정상적으로 사용할 수 없게 되면 가용성 침해**로 볼 수 있다.

---

## CIA 한 번에 기억하기

- 기밀성: 못 보게
- 무결성: 못 바꾸게
- 가용성: 못 죽게

## 추가적인 보안 속성

CIA 외에도 실제 보안에서는 인증성, 추적가능성, 부인방지 등의 속성이 중요하다.

### 인증성 (Authentication / Authenticity)

사용자 또는 데이터가 주장하는 대상이 실제로 맞는지 확인하는 성질이다.

쉽게 말하면 **"너 진짜 누구야?"**를 확인하는 것이다.

예:
- ID/PW 로그인
- OTP
- 인증서
- 전자서명을 통한 송신자 확인

---

### 추적가능성 (Accountability)

누가 언제 어떤 행동을 했는지 나중에 확인할 수 있도록 하는 성질이다.

예:

`02:13 / adminA / 방화벽 정책 변경`

이런 기록이 남아 있으면 사고가 발생했을 때 행위자를 추적할 수 있다.

추적가능성을 보장하는 대표적인 수단이 **감사로그(Audit Log)**이다.

---

### 부인방지 (Non-repudiation)

사용자가 자신이 수행한 행위를 나중에 부인하지 못하도록 증거를 남기는 성질이다.

쉽게 말하면 **"해놓고 안 했다고 하지 못하게 하는 것"**이다.

전자서명이 대표적인 수단이다.

---

## 인증과 인가

### 인증 (Authentication)

사용자가 누구인지 확인하는 과정이다.

예: ID/PW, OTP, 인증서

### 인가 (Authorization)

인증된 사용자가 특정 자원이나 기능을 사용할 권한이 있는지 확인하는 과정이다.

정리:
- 인증 = 너 누구야?
- 인가 = 너 이거 해도 돼?

---

## 감사로그 (Audit Log)

감사로그는 **누가, 언제, 무엇을 했는지 기록하는 로그**이다.

일반 로그가 시스템에서 어떤 일이 발생했는지 확인하는 데 초점이 있다면, 감사로그는 사용자나 관리자의 **행위 추적**에 초점이 있다.

대표적인 기록 대상:
- 로그인 및 로그아웃
- 계정 생성 및 삭제
- 권한 변경
- 관리자 기능 실행
- 파일 삭제
- DB 또는 시스템 설정 변경

### 감사로그의 주요 용도

1. 사고 발생 시 행위자 추적
2. 보안 감사
3. 침해사고 조사
4. 변경 이력 확인
5. 부인방지 지원

### 장애 분석에도 사용할 수 있는가?

가능하다. 다만 감사로그의 1차 목적은 장애 로그가 아니라 **행위 추적**이다.

예:

`10:02 adminA가 방화벽 정책 변경`

`10:05 서비스 통신 실패 시작`

이 경우 감사로그를 통해 장애 직전 어떤 관리 작업이 있었는지 확인할 수 있으므로 장애 원인 분석에 큰 도움이 된다.

반대로 CPU 폭주, 메모리 부족, 애플리케이션 예외, DB Timeout 같은 문제는 시스템 로그, 애플리케이션 로그, 모니터링 지표를 확인하는 것이 더 적절하다.

정리:

- 감사로그 = 누가 무엇을 했는가
- 시스템/애플리케이션 로그 = 시스템에서 무엇이 일어났는가

## 보안 문제를 보는 기본 흐름

보안 개념은 다음 흐름으로 보면 이해하기 쉽다.

`자산 → 위협 → 취약점 → 공격 → 침해 → 보안 대책`

예를 들어 웹 애플리케이션에서 입력값 검증이 부족하면 SQL Injection 공격에 악용될 수 있고, 그 결과 DB 정보가 유출될 수 있다. 이때 Prepared Statement와 같은 방식이 대응책이 된다.

---

## 시험 포인트 요약

- 기밀성: 정보의 비인가 열람 방지
- 무결성: 정보의 비인가 변경 및 훼손 방지
- 가용성: 정상적인 서비스 이용 보장
- 인증성: 사용자나 데이터의 진위 확인
- 추적가능성: 누가 어떤 행위를 했는지 확인 가능
- 부인방지: 자신의 행위를 나중에 부인하지 못하게 함
- 감사로그: 사용자 및 관리자의 행위 추적
- 인증과 인가를 구분할 것
- MAC은 문맥에 따라 MAC Address와 Message Authentication Code가 다르므로 주의

## 실무 연결

서비스 장애나 DDoS는 단순 운영 문제뿐 아니라 가용성 침해로도 볼 수 있다. 모니터링과 장애 대응은 보안의 가용성 측면과 연결되며, 감사로그는 장애 직전의 관리자 작업이나 설정 변경을 확인할 때도 유용하다.
